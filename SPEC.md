# SPEC 1 — с AI-новостей на клубную афишу Гамбурга

Статус: **v2** (04.11.2026), все вопросы закрыты. Код не писать до «утверждаю» внизу.
Исполнение: ночью через `/goal`, утром отчёт.

## Для кого и зачем
Для Kirill и друзей, которые ходят в клубы Гамбурга. Сейчас бот показывает AI-новости из шаблона,
то есть 0% нужного контента. Цель: открыть ленту и за минуту увидеть, что идёт в ближайшие 14 дней,
и одним нажатием перейти на страницу события.

## Решения (ответы Kirill, 04.11)
1. Берём **все** события площадок: концерты, вечеринки, чтения, маркеты. Модель только ставит метку
   типа (`Konzert` / `Party` / `Sonstiges`), ничего не выбрасывает. Фильтр по метке будет в следующей итерации.
2. Горизонт: **ближайшие 14 дней**. Collector запускается каждый день, новые дни подтягиваются сами.
3. Строка ленты: **дата, время начала, клуб, название как на сайте, одна фраза «что это»**. Цены нет.
   `Fr 06.11 20:00 · Molotow · Fahnenflucht — Deutschpunk`
4. Фраза «что это» **по-немецки**.
5. Нажатие на строку открывает **страницу события**. Источник без отдельных страниц событий в эту спеку
   не входит.
6. Старые AI-данные **удалить** из базы: находки, материалы и источники шаблона.
7. События **ABGESAGT / AUSVERKAUFT / VERSCHOBEN скрываются** (не показываются в ленте и сводке).
8. Многодневное событие — одна строка с датой и временем начала.
9. **Утренняя сводка** (после сбора, 07:00 Гамбург): Пн–Чт — события сегодня; Пт — пятница, суббота,
   воскресенье; Сб — суббота; Вс — воскресенье.
10. **Дубли между источниками** (одно событие с сайта клуба и из агрегатора): одна строка, ссылка
    на сайт клуба. Одно событие = та же площадка + та же дата + похожее название.

## Что меняем и где
- `db/schema.sql`: у `materials` поля `starts_at` (Europe/Berlin) и `venue`; у `findings` — `event_type`.
  Источники шаблона заменить новыми (`kind` = имя парсера).
- `collector/`: по парсеру на источник, только события в ближайшие 14 дней, без отменённых и
  распроданных, `url` = страница события (ключ против дублей внутри источника) + проверка дублей между
  источниками.
- `worker/main.py`: промпт v2 — тип события и одна фраза «что это» по-немецки, без фильтра `about_ai`.
- `bot/`: формат строки, сортировка по `starts_at`, окно 14 дней, сводка по дням недели (решение 9).
- `tests/`: `unittest`, на каждый парсер сохранённая страница (fixture), без сети.

## Задачи (по порядку; одна задача = один коммит; тест на каждую)
- **T1** Схема: новые поля, источники, удаление AI-данных (findings → materials → sources шаблона).
  Тест: схема применяется дважды без ошибок.
- **T2** Grünspan. **T3** Uebel & Gefährlich. **T4** Molotow. **T5** Knust.
  Тест каждого: на сохранённой странице ≥ 1 событие, у каждого название, дата, время, url;
  отменённые отфильтрованы.
- **T6** Дубли между источниками. Тест: два одинаковых события из разных источников → одно, ссылка клуба.
- **T7** Промпт worker v2. Тест: разбор ответа модели и проверка полей без сети.
- **T8** Лента: формат строки, сортировка, окно 14 дней. Тест: формат строки.
- **T9** Сводка по дням недели. Тест: для каждого дня недели правильное окно дат.
- **T10–T14** Кандидаты по правилу 45 минут: ohschonhell, Clubkombinat, Docks, Mojo, Pudel.
  Подключённый — свой коммит с тестом; неподключённый — строка в бэклог с причиной.
- **T15** Push → Coolify Redeploy → Execute Now → проверка логов worker и бота → замер «после»,
  скриншоты ленты. Бот упал → откат на предыдущий коммит, Redeploy, запись в отчёт.

Зависимости: T1 → T2–T5 → T6 → T7 → T8 → T9 → T10–T14 → T15.
